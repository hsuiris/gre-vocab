# Neon Postgres Migration Plan

This backend currently uses local SQLite through `data/app.db`. That is fine for local testing, but App Store users need a public backend and managed database.

## Target

- API host: a public Node host such as Render, Fly.io, Railway, or a VPS.
- Database: Neon Postgres.
- Required environment variable: `DATABASE_URL`.
- Local fallback during development can remain SQLite until the API is switched.

## Minimal Schema Changes

The current table shape can move almost directly to Postgres:

- Keep string ids generated by the app (`usr_*`, `word_*`).
- Change `INTEGER` boolean fields to `boolean`.
- Change timestamp `TEXT` fields to `timestamptz`.
- Change `goal_json TEXT` to `jsonb`.
- Keep soft delete on `users.deleted_at` and `words.deleted_at`.

## Migration Order

1. Create Neon project and copy the pooled `DATABASE_URL`.
2. Add a Postgres database adapter behind the existing `backend/db.js` API: `q`, `one`, `all`, `exec`.
3. Convert `migrations/0001_initial.sql` to Postgres syntax.
4. Run migrations against Neon.
5. Seed `assets/words.json` into Neon.
6. Deploy backend with `DATABASE_URL`.
7. Point the app to the deployed API URL.

## App Store Requirement

Do not submit a production build that points to `localhost:3001`. The iOS app must call the deployed HTTPS API.

## Deferred

- File upload/CDN for avatars. Current profile data stores `avatar_url`.
- Google OAuth. Current UI only has the setting entry point.
- Admin user management. Current `/admin` page manages words only.
